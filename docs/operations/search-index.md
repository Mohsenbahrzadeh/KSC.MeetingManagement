# نمایهٔ جست‌وجوی محتوایی

جست‌وجوی محتوایی با Lucene.NET انجام می‌شود. پایگاه‌داده منبع حقیقت است و Lucene یک نمایهٔ مشتق‌شده است؛ فایل‌های نمایه را می‌توان حذف و از دادهٔ جاری بازسازی کرد. فعلاً متن فقط از نسخهٔ مصوب صورت‌جلسه و فرادادهٔ پیوست (نام فایل و نوع محتوا) گرفته می‌شود؛ فایل پیوست دانلود یا متن آن استخراج نمی‌شود.

## مسیر و پشتیبان‌گیری

- مسیر پیش‌فرض: `App_Data/lucene` در کنار خروجی API.
- مسیر قابل تنظیم با `Search__IndexPath` است. مسیر باید روی دیسک پایدار، قابل نوشتن برای کاربر سرویس و دارای فضای کافی باشد؛ از volume پایدار استفاده کنید، نه filesystem موقت کانتینر.
- نمایهٔ Lucene پشتیبان حقیقت نیست؛ در صورت بازیابی DB از backup قدیمی‌تر، rebuild اجباری انجام دهید. backup فایل‌های Lucene فقط برای کاهش زمان بازیابی مفید است و باید با زمان snapshot دیتابیس هماهنگ شود.
- جدول `search_index_changes` در همان تراکنش تغییر محتوای جلسه نوشته می‌شود. رکورد تا اعمال تغییر روی Lucene باقی می‌ماند و با درخواست‌های بعدی Search تخلیه می‌شود. پاک کردن دستی صف ممکن است محتوای نمایه را کهنه کند؛ به جای آن از rebuild استفاده کنید.

## بازسازی

کاربر دارای مجوز `OrganizationManage` می‌تواند endpoint tenant-scoped زیر را اجرا کند:

```http
POST /api/v1/search/rebuild
```

پس از بازیابی/ارتقای دیتابیس، حذف ناخواستهٔ نمایه یا نشانهٔ نتایج کهنه، این endpoint را اجرا و پاسخ `IndexedSourceRecords` و لاگ API را بررسی کنید. بازسازی هر tenant فقط اسناد همان tenant را جایگزین می‌کند. migration `20261108092809_AddSearchIndexChanges` باید پیش از استفاده اعمال شده باشد.

## توپولوژی استقرار و نگه‌داری

نسخهٔ فعلی از یک `IndexWriter` درون‌پردازه‌ای استفاده می‌کند و صف durable را هر نمونهٔ API می‌خواند؛ بنابراین تا افزودن claim/lease توزیع‌شده و همگام‌سازی writer، فقط **یک نمونهٔ فعال API برای هر `Search__IndexPath`** اجرا کنید و آن مسیر را بین نمونه‌ها share نکنید. برای چند نمونهٔ API، هر کدام باید مسیر محلی مستقل داشته باشد و تغییرات به همهٔ نمایه‌ها fan-out شوند؛ این قابلیت هنوز پیاده‌سازی نشده است.

صف را پایش کنید:

```sql
select "TenantId", count(*) from search_index_changes group by "TenantId";
```

ماندن صف معمولاً نشان‌دهندهٔ خطای دسترسی/فضای دیسک در مسیر Lucene یا شکست پردازش است. از حذف مستقیم ردیف‌ها خودداری کنید؛ پس از رفع علت، درخواست‌های Search صف را دوباره پردازش می‌کنند یا endpoint بازسازی را اجرا کنید.
