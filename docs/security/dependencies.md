# بررسی وابستگی‌ها و فرایند Patch (TASK-065)

## اسکن خودکار
- **بسته‌های NuGet:** در CI، `dotnet list package --vulnerable --include-transitive` اجرا می‌شود و اگر آسیب‌پذیری گزارش شود Build قرمز است. همین بررسی هر دوشنبه (زمان‌بندی هفتگی) هم اجرا می‌شود تا آسیب‌پذیری‌های تازهٔ کشف‌شده در کد بدون تغییر هم دیده شوند.
- **بسته‌های منسوخ:** `dotnet list package --deprecated` (دستی، ماهانه). وضعیت 2026-10-20: هیچ آسیب‌پذیری گزارش نشد؛ تنها مورد منسوخ، `xunit 2.9.3` (برچسب Legacy، جایگزین `xunit.v3`) است و فقط در پروژه‌های آزمون استفاده می‌شود.
- **تصاویر کانتینر:** هنوز Dockerfile/Compose در مخزن نیست. هنگام اضافه‌شدن تصاویر API/Web و LiveKit/coturn: اسکن با Trivy (`trivy image --severity HIGH,CRITICAL --exit-code 1 <image>`) به CI اضافه شود و نسخهٔ تصویر پایه ثابت (نه `latest`) باشد. تا آن زمان این بند **انجام‌نشده** است.
- **JavaScript:** برنامه فعلاً npm مستقیم ندارد؛ با افزودن SDK رسانهٔ مرورگر (TASK-047) باید `npm audit` و قفل نسخه اضافه شود.

## رسیدگی به آسیب‌پذیری
| شدت | زمان بررسی | زمان رفع/کاهش | اقدام |
|---|---|---|---|
| Critical | همان روز | ≤ ۴۸ ساعت | به‌روزرسانی یا غیرفعال‌سازی ویژگی؛ Patch فوری و اطلاع به مالک محصول |
| High | ≤ ۲ روز کاری | ≤ ۷ روز | PR مستقل `chore/deps-…`، تست کامل، ادغام |
| Medium | ≤ ۵ روز کاری | ≤ ۳۰ روز | در Sprint بعدی |
| Low | ماهانه | بهترین تلاش | همراه به‌روزرسانی دوره‌ای |

مراحل: ۱) تأیید قابل‌بهره‌برداری بودن در این برنامه (کاربرد واقعی بسته) ۲) به‌روزرسانی نسخه (ترجیحاً Patch/Minor) یا جایگزینی ۳) `dotnet build` و `dotnet test` ۴) PR با شمارهٔ هشدار (CVE/GHSA) در توضیح ۵) ثبت تصمیم در صورت پذیرش ریسک (دلیل، تاریخ بازبینی). اگر Patch موجود نیست: کاهش ریسک (غیرفعال‌سازی مسیر، قانون شبکه) و بازبینی هفتگی.

## به‌روزرسانی دوره‌ای
- ماهانه: `dotnet list package --outdated`، به‌روزرسانی Patch/Minor در یک PR.
- با هر نسخهٔ LTS جدید .NET: بررسی `global.json` و ارتقا. SDK در CI از `global.json` گرفته می‌شود.
- Dependabot (GitHub) برای NuGet و GitHub Actions توصیه می‌شود؛ فعال‌سازی آن نیازمند تنظیمات مخزن است و انجام نشده است.
