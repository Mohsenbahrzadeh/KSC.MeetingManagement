# Threat Model — مدیریت جلسات (TASK-062)

**تاریخ:** 2026-10-20 — **وضعیت:** نسخهٔ اول، بر اساس کد موجود در `main`  
**روش:** STRIDE روی مرزهای اعتماد اصلی. برای هر ریسک: کنترل پیاده‌شده، شواهد (کد/آزمون) و ریسک باقی‌مانده. موارد «باز» هنوز پیاده نشده‌اند.

## ۱. دامنه، دارایی‌ها و بازیگران
- **دارایی‌ها:** داده‌های هر سازمان (Tenant): جلسات، صورت‌جلسه و مصوبات، پیوست‌ها، شرکت‌کنندگان؛ توکن‌های دعوت مهمان؛ توکن‌های ورود به اتاق رسانه؛ کلید و رمز سرور رسانه؛ ثبت ممیزی.
- **بازیگران:** کاربر سازمانی با نقش (مالک، مدیر، برگزارکننده، منشی، تأییدکننده، ممیز، شرکت‌کننده)، مهمان خارجی با دعوت، مهاجم ناشناس، کاربر Tenant دیگر، مدیر زیرساخت.
- **مرزهای اعتماد:** مرورگر ↔ Web (Blazor Server) ↔ API ↔ PostgreSQL / فایل‌ها؛ مرورگر ↔ سرور رسانه (LiveKit/TURN) با توکن صادرشده از API.

## ۲. وضعیت احراز هویت (مهم)
ورود کاربر واقعی (ADR-0003) **هنوز پیاده نشده است**. در محیط واقعی هیچ Scheme احراز هویتی ثبت نیست، پس همهٔ endpointهای محافظت‌شده 401 می‌دهند (بسته در حالت پیش‌فرض). هدر آزمایشی `X-Test-User` فقط در پروژهٔ آزمون ثبت می‌شود و در کد API نیست. تا پیاده‌سازی ورود، بیشتر کنترل‌های زیر با آزمون یکپارچه ثابت شده‌اند نه با کاربر واقعی. **ریسک باز R-00:** تکمیل ورود، انقضای نشست، و قفل پس از تلاش ناموفق.

## ۴. موارد باز (به ترتیب اولویت)
1. R-00: ورود واقعی و مدیریت نشست.
2. R-11: استقرار و سخت‌سازی LiveKit/coturn و آزمون روی سرور واقعی.
3. R-22: سرصفحه‌ها و CSP برنامهٔ Web.
4. R-16: قاعدهٔ تأییدکننده ≠ نویسنده (اختیاری، قابل پیکربندی).
5. R-17: ممیزی و مجوز مدیریت نقش‌ها هنگام پیاده‌سازی.
6. R-19: اسکن بدافزار پیوست‌ها.
7. انتقال ممیزی به ذخیره‌سازی غیرقابل تغییر.
